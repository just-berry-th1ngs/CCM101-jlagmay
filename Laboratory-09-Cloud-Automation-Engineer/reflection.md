# Reflection

## 1. Why is automation critical when managing hundreds of cloud servers?

Doing tasks by hand on hundreds of servers is slow and full of mistakes. A script does the same task the same way every time. With cron, the task also runs on a schedule, so nobody has to remember it. This saves time and keeps the servers consistent.

## 2. What are the dangers of automation?

Automation can spread a mistake very fast. If a script has a typo, such as deleting the wrong folder, and it runs on 1,000 servers, the damage happens on all of them at once. Data could be lost everywhere before anyone notices. Scripts should be tested on one server first, and backups should be kept.

## 3. How is a Bash script different from a Docker Compose YAML file?

A Bash script is a list of commands that run step by step. It tells the computer how to do a task. A Docker Compose YAML file describes what I want, such as the containers, ports, and settings, and Docker sets it up. Bash is for actions, and YAML is for setup.

## 4. How has my understanding of Cloud Computing changed?

At the start, I only knew the basic cloud ideas. In the labs, I learned to deploy containers, monitor them with logs and metrics, secure a server with a firewall, and now automate tasks. I now see that the cloud is many parts that must work together and be kept safe and running.
